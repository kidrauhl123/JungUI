# JungUI

用这个库做界面时遵守。准则一条一条加，不预先写满。

## 文案与注释

- 文案、注释越少越好。
- 不要加 Hero，除非用户明确要求。
- 不要把用户的 prompt 写成前端里的文案或注释。

## 容器分离

一个容器最多一个**强**边界信号，其余降到 whisper（1px、≤10% 不透明度）。不是"只能用一种"，见下方实测。

| 手段 | 用于 | 本库 |
| :--- | :--- | :--- |
| 仅边框 | 高密度工具界面，内外同底色 | **默认**。卡片、面板、输入框：`1px solid var(--line)`，底色与页面相同 |
| 仅色差 | 内容流、分组区块 | 小元素用 `--soft`、`--code` |
| 色差 + 阴影 | 浮层：弹窗、菜单、悬浮面板 | 浮层不加描边 |
| 纯留白 | 能靠邻近分组的，不要画框 | 优先于新增边框 |

- 阴影不能独立承载层级。投影在同色底和深色模式下会消失，浮层必须同时提亮或压暗底色。
- 深色模式不要沿用"同底色 + 仅边框"。白描边在纯黑上会发光；改成提亮底色 + 极弱描边。
- `--line` 是装饰线，不承担辨识：实测浅色 1.26:1、深色 1.70:1。WCAG 1.4.11 的 3:1 只约束"用户据此识别控件及其状态"的视觉信息，纯信息容器豁免。
- 交互状态用 ring：`box-shadow: 0 0 0 1px <color>`，不占布局、不改变尺寸。先例见 `promotion-code`、`command-search`。

### 案例实测（2026-10-12，读取各站计算样式）

原先把三种手段当成互斥流派，案例归属有三处错。

- GitHub ✅ 仅边框：`.Box` = `#fff` + `1px #d1d9e0`，无阴影。
- iOS 设置 ✅ 仅色差：HIG 用 grouped 三级背景色表达层级。
- Notion 页面块 ✅ 仅色差；但 Notion 官网同时存在仅阴影和仅边框的卡片。同一产品按语境切换，不存在"一个产品一种流派"。
- Linear ❌ 非仅边框：暗色卡片 = `#0f1011` 压在 `#08090a` 页面上 + `rgba(255,255,255,.05)` 描边，所谓阴影其实是 `0 0 0 1px` 的 ring。
- Stripe ❌ 非仅阴影：docs 的 `.Card--bordered` = 透明底 + `1px #e3e8ee`，无阴影。
- Material ❌ 非仅阴影：官方文档 "represents elevation primarily using tonal overlay … in addition to shadows"。

未核实：Linear 应用内、Stripe Dashboard、Notion 编辑器需登录，只测了公开站点。
