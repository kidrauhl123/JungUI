# JungUI

用这个库做界面时遵守。准则一条一条加，不预先写满。

## 文案与注释

- 文案、注释越少越好。
- 不要加 Hero，除非用户明确要求。
- 不要把用户的 prompt 写成前端里的文案或注释。

## 容器分离的四种主流流派

严格控制**只用一种显式边界手段**，切忌边框、色差、阴影多重叠加。

| 设计手段 | 适用场景与视觉风格 | 典型案例 |
| --- | --- | --- |
| **仅边框（Border-only）**<br>内外同底色（纯白或纯深灰） | 高信息密度、极简、工具型软件。<br>页面极其轻盈、通透、克制，无大色块压迫感。 | GitHub 仓库页、SaaS 控制台数据卡片、Stripe 文档卡片 |
| **仅色差（Fill-only）**<br>无边框，靠浅灰/纯白区分 | 消费级应用、卡片流、内容消费类。<br>视觉柔和、现代，由色彩自然过渡形成，视觉负担轻。 | iOS 设置、资讯流 |
| **仅阴影（Shadow-only）**<br>无边框，同色靠投影分离 | 模拟物理层级（Elevation）、浮层强调。<br>突出悬浮感与点击感，适用于弹窗、菜单、关键模块。 | Material Design |
| **无容器（No-container）**<br>不围合内容，靠留白、行分隔线、字号字重分组 | 文档、表单、设置列表、文章等线性内容。<br>最干净，信息直接落在页面上。 | Notion 页面、Apple 备忘录、Stripe 首页 |

- 不确定时先不用容器；内容之间确实需要分隔，再从上面选一种手段。
- 容器嵌套时，内层不要再用同一种手段，优先直接去掉内层容器。
- **仅边框的判定看"内外同底色"**：底色比页面亮、再补一条半透明描边，就是色差 + 边框两重（linear.app 实测如此），不算仅边框。
- 行分隔线不算容器：它只分行、不围合内容，属于无容器这一派内部的手段。


## 设计 token

- 间距只用 4 / 8 / 12 / 16 / 24 / 32 / 48，不写其他数。
- 圆角全项目最多 2 档，同一层级的元素用同一档。
- 字号只用 12 / 14 / 16 / 20 / 24，正文用 14 或 16。
- 颜色：一个主色，其余用中性灰。成功、警告、错误色只用于状态。
- 可交互元素要有 hover、focus、disabled，focus 必须可见。
- 所有值写成 CSS 变量，不在组件里写死。

## 动效

- 只做功能性动效：展开收起、浮层出现、状态切换。
- 装饰性动效尽量减少甚至不做：入场动画、悬浮位移、视差、发光。
- 时长 150–250ms，只动高度、透明度、颜色，不做弹跳和回弹。

## 布局

- 内容默认左对齐。居中只用于登录页、空状态这类只有一个焦点的页面。
- 限制宽度：文章和表单最大 640，其他页面最大 1200，超出后居中留白。
- 宽度写成 CSS 变量（如 `--content-width`），不在各个组件里分别限制。
- 不套"居中大标题 + 三列卡片"这类固定排版，按内容本身的结构排。
- 元素沿同一条左边线对齐，同一屏的对齐线越少越好。
- 一屏只有一个主操作，其余用次要样式。
- 层级用字号和字重表达，不靠加颜色。

## 可点击区域

- 可点击元素最小高度 32，触屏场景 44。
- 图标按钮的图形可以小，但点击区域要用内边距补到 32 以上。
- 相邻的可点击元素间距至少 8。
- 列表行、卡片如果可点击，整块都能点，不只是文字。
